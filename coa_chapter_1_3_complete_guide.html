The Big Picture This chapter answers one question: how does a program — text written by a human — end up as electrical actions inside a CPU? The journey is: high-level language → assembly language → machine code (binary) → memory → CPU fetch → decode → execute. Every section of this chapter zooms into one part of that journey.

0 · Prerequisites You Need First

Clarification The lecture notes begin by using words like instruction, register, memory, and address without defining them. This section defines every one of those words from first principles, so that nothing later in the guide will feel like magic.

0.1 What is a computer?

Strip away the screen, keyboard, and case, and a computer is a machine that does exactly three things: it stores numbers, it transforms numbers (add, compare, move), and it follows a stored list of steps that says which transformations to do and in what order. That stored list of steps is a program. The computer is special among machines because the list of steps is itself stored as data inside the machine — change the list and the same hardware becomes a calculator, a word processor, or a game. This idea is called the stored-program concept.

0.2 What is a CPU?

The Central Processing Unit (CPU) — also called the processor — is the part that actually performs the steps. Think of it as an extremely fast, extremely obedient, and extremely literal worker. It can do only a small set of very simple things (add two numbers, move a number from one place to another, compare two numbers, jump to a different step), but it does billions of them per second. Inside the CPU there are three sub-parts you will meet throughout this chapter:

  • Control Unit (CU) — the manager. It reads each instruction, figures out what it means, and sends control signals telling every other part what to do and when.
  • Arithmetic Logic Unit (ALU) — the calculator. It performs all arithmetic (add, subtract, multiply, divide) and logical (AND, OR, NOT, shift) operations.
  • Registers — a handful of tiny, ultra-fast storage cells inside the CPU itself (explained below).

0.3 What is memory?

Main memory (RAM) is a huge array of numbered storage cells that sits outside the CPU. Picture a street with millions of identical mailboxes in a row. Each mailbox has a unique number — its address — and holds a small fixed amount of information — its contents (usually one byte = 8 bits). Two completely different ideas live in memory, both stored as numbers:

  • Instructions — the steps of the program.
  • Data — the values the program works on (numbers, text, pixels).
Key Idea The address of a memory cell and the contents of that cell are different things. Address 2000 is a location; what is stored at location 2000 is data (or an instruction). Confusing "address" with "contents of the address" is the single most common beginner mistake in this entire chapter.

0.4 What is an address?

An address is simply the number that identifies one memory cell, exactly like a house number on a street. If a CPU has address wires that can carry a 16-bit number, it can name 216 = 65,536 different memory cells. When you read "memory location 2000H", the H means the number is written in hexadecimal (explained in 0.10), so it is just one particular mailbox number.

0.5 What is a register?

A register is a tiny storage cell built inside the CPU. You can think of registers as the CPU's hands: memory is a large warehouse across the street, but the CPU can only work on what it is currently holding. Registers are few (from 8 to a few dozen in simple processors), each holds one small number, and they are the fastest storage in the machine. Registers you will meet in this chapter:

0.6 What is a program? What is an instruction?

From Lecture Notes The lecture notes define these as:

Definitions (Lecture 1.3.1) Instruction — an order given to a computer processor by a computer program to compute any task.
Program — a sequence of machine instructions.
Language — a system of communication.
Programming language — the set of rules a programmer uses to develop software or write instructions a computer can understand.

Clarification An analogy: a program is a recipe; an instruction is one numbered step of that recipe ("add 2 eggs", "stir for 1 minute"). The CPU is a cook who can read exactly one step at a time, perform it, and move to the next. Every CPU family has its own fixed menu of steps it understands — that menu is its instruction set (Section 2).

0.7 What is machine code? Why binary?

The CPU is built from millions of microscopic switches (transistors), and a switch has exactly two stable states: on or off. That is why everything inside a computer is encoded with just two digits, 0 and 1 — binary. From Lecture Notes As the lecture notes put it: "Turn the switch on to represent a one; turn it off to represent a zero." An instruction, then, is physically nothing more than a pattern of bits — for example 10110000 00000101. That bit pattern is machine code: the only language the CPU hardware executes directly. Humans almost never write machine code by hand; we write assembly or high-level languages and let translator programs produce the bits (Section 4).

0.8 What is data? What is an operand?

Data is any value a program manipulates: the number 55, the letter 'A', a pixel color. An operand is the specific piece of data (or the place holding it) that one instruction works on. In the instruction ADD AX, BX the operation is "add" and the operands are the values in registers AX and BX.

0.9 What is an opcode?

Every instruction the CPU understands has two parts:

Opcode"WHAT to do"
Operand(s) / Address field"to WHOM / with WHAT"

The opcode (operation code) is the part of the instruction that says which operation to perform — add, move, jump, halt. It must be encoded as bits because the CPU's decoder is hardware that reads bits. For example, in a toy instruction set, 0001 might mean "ADD" and 0010 might mean "MOVE". The operand field says where the data is — a register number, a memory address, or a literal value.

0.10 Binary and hexadecimal in 2 minutes

  • Binary (base 2): digits 0 and 1. Each position doubles: 1011 = 8+0+2+1 = 11 in decimal. One binary digit is a bit; 8 bits are a byte.
  • Hexadecimal (base 16): digits 0–9 then A=10, B=11, C=12, D=13, E=14, F=15. Hex exists because binary is tedious for humans: each hex digit is exactly 4 bits, so one byte is exactly two hex digits. 1111 1111 = FF = 255. You will see suffixes: 55H or 0x55 mean hex; 55 alone usually means decimal.
Quick Conversion Drill 25H = 2×16 + 5 = 37 decimal = 0010 0101 binary. When the notes say "M[40H] = 25H" they mean: memory cell number 0x40 holds the byte 0x25.

0.11 Why does the CPU need instructions at all?

Because the CPU is hardware: it cannot infer your intent. Hardware only reacts to electrical patterns. An instruction is the contract between human intention and hardware behavior — a bit pattern that the CPU's control unit was physically wired to interpret as a specific action. Nothing else can drive the CPU.

2 · Instruction Set Architecture (ISA)

From Lecture Notes The lecture notes introduce the ISA with these statements:

From the Lecture Document "The instruction set provides commands to the processor, to tell it what it needs to do. The instruction set consists of addressing modes, instructions, native data types, registers, memory architecture, interrupt and exception handling, and external I/O."

"An instruction set architecture (ISA) is an abstract model of a computer. A realization of an ISA is called an implementation. An ISA permits multiple implementations that may vary in performance, physical size, and monetary cost, because the ISA serves as the interface between software and hardware."

"Software written for an ISA can run on different implementations of the same ISA. This has enabled binary compatibility between different generations of computers, and the development of computer families."

2.1 What is an ISA, really?

Clarification An ISA is the complete contract that a CPU family offers to programmers. It answers: "If you give me a machine instruction, what exactly will I do?" It specifies, among other things:

  • The instruction set — every operation the CPU can perform (ADD, MOV, JMP…) and how each is encoded in bits.
  • Registers — which registers exist, their sizes, and their special roles.
  • Native data types — the sizes and formats the hardware understands (8/16/32/64-bit integers, floating-point formats).
  • Addressing modes — the legal ways an instruction may refer to its data (Sections 9–10).
  • Memory architecture — how memory is addressed (byte-addressable? how large an address?).
  • Interrupt / exception handling — how the CPU reacts to hardware signals and errors.
  • External I/O — how instructions communicate with devices (Section 14.3).
Analogy An ISA is like the rules of chess. The rules define the pieces, the legal moves, and how you win — but they say nothing about whether the board is wood, plastic, or a phone screen. Many physical chess sets (implementations) can host the same game (ISA). Similarly, the x86 ISA defines what every instruction does; Intel and AMD both build physically different chips that play by those same rules.

2.2 ISA vs Microarchitecture vs Hardware Implementation

Clarification External Research Beginners constantly mix these three layers up. They are distinct:

LayerWhat it isExample question it answersExample
ISA (architecture)The programmer-visible contract: instructions, registers, data types, addressing modes."What does ADD do, and how is it encoded?"x86, ARM, MIPS, RISC-V
MicroarchitectureA specific internal design that implements an ISA: pipeline depth, cache layout, execution units."How many pipeline stages? How is ADD executed in hardware?"Intel Skylake vs AMD Zen — both implement x86 differently
Hardware implementationThe physical chip: transistors, silicon process, clock speed, power."5 nm or 7 nm? 3 GHz or 5 GHz?"A specific Core i7 part number

This is exactly what the lecture notes mean by "an ISA permits multiple implementations that may vary in performance, physical size, and monetary cost." Two CPUs can run the same binary program (same ISA) while one finishes faster (different microarchitecture and hardware). That property — binary compatibility — is why a program compiled for x86 in 1995 still runs on a 2025 x86 laptop, and it is why the notes call the ISA "one of the most important abstractions in computing today."

Exam Note A classic 2-mark question: "Why is the ISA called the interface between software and hardware?" Answer: software is written against the ISA (compilers generate instructions the ISA defines); hardware is built to satisfy the ISA (the control unit decodes exactly those instructions). Neither side needs to know the other's internal details — they only need to honor the shared contract.

3.1 Machine Language

From Lecture Notes The notes say: machine language is the language closest to the hardware itself; programs in it are highly efficient; and it is in the form of binary code (0 and 1), which makes the codes difficult to memorise.

Clarification "Closest to hardware" means there is no translation at all between the program and what the CPU executes — the program is the bit patterns. "Highly efficient" means zero translation overhead and total control, not that humans write it quickly — they do not.

The light-bulb example (from the lecture notes)

From Lecture Notes The notes give a tiny imaginary machine — a programmable light bulb — whose entire machine language is five binary commands:

Machine code (binary)Meaning
00000000STOP PROGRAM
00000001TURN BULB ON
00000010TURN BULB OFF
00000100DIM BULB BY 10%
00001000BRIGHTEN BULB BY 10%

Read this table carefully, because it teaches the essence of machine language: each distinct bit pattern is wired to one distinct hardware action. A "program" for this bulb is just a sequence of these bytes. For example, the byte sequence 00000001 00001000 00001000 00000000 means: turn on, brighten, brighten, stop. The bulb's control circuit reads each byte and performs the matching action — no understanding, no intelligence, just wiring. That is precisely how a real CPU treats machine code, only with hundreds of patterns instead of five.

Clarification A realistic modern example: on a real x86 CPU, the byte 0x90 (10010000) is the machine instruction NOP ("do nothing"), and 0xB8 begins a "load a value into AX" instruction. Same principle as the bulb — one bit pattern, one hardware action — just a much bigger vocabulary. You will see this concretely in Section 6.

3.2 Assembly Language

From Lecture Notes The notes define assembly language as a low-level programming language in which there is a very strong (but often not one-to-one) correspondence between the language and the architecture's machine code instructions. Each assembly language is specific to a particular computer architecture, unlike high-level languages which are generally portable. Assembly may also be called symbolic machine code. It is converted into executable machine code by a utility program called an assembler; the conversion process is called assembly, and the time at which it happens is assembly time.

Clarification Assembly is machine language wearing a name tag. Instead of memorising that 00000001 turns the bulb on, you write ON; instead of 10110000 00000101, you write MOV AX, 5. The assembler is a simple dictionary-lookup program that replaces each mnemonic with its bit pattern. "Not one-to-one" means some assembly lines (macros, directives) can expand to several machine instructions or to no instruction at all. Section 5 covers assembly in full depth.

3.3 High-Level Language

From Lecture Notes The notes describe a high-level language (HLL) as a programming language designed to simplify computer programming, "high-level" because it is several steps removed from the actual code run on the processor. HLL source code has easy-to-read syntax that is later converted into a low-level language a specific CPU can run. Rather than dealing with registers, memory addresses and call stacks, HLLs deal with variables, arrays, objects, complex arithmetic or boolean expressions, subroutines and functions, loops, threads, locks — with a focus on usability over optimal program efficiency. Few, if any, HLL elements translate directly into a machine's native opcodes.

Clarification The key trade: one line of Python (total = sum(prices)) may expand into dozens of machine instructions. You give up fine control and some speed; you gain readability, portability, and development speed. One HLL statement ↔ many machine instructions; one assembly statement ↔ (usually) one machine instruction. That ratio is the defining difference between the levels.

5 · Assembly Language from Zero

From Lecture Notes The notes describe assembly language instructions as "a human-readable, symbolic representation of the machine instructions that a processor can execute," using mnemonics (abbreviations) for operations and operands, corresponding directly to the processor's instruction set. Each assembly instruction typically specifies an operation and one or more operands.

5.1 Why does assembly exist?

Clarification Because humans are bad at binary but sometimes need machine-level control. Assembly keeps the full power of machine code (every instruction is available) while replacing bit patterns with memorable names. You write assembly when you must control the hardware exactly: operating-system kernels, device drivers, microcontroller firmware, boot code, and performance-critical inner loops.

5.4 The lecture's example — dissected completely

From Lecture Notes The notes give this three-line program. Do not skim it — we will take it apart piece by piece.

LOOP: MOV AX, 10   ; Move the immediate value 10 into the AX register
      ADD AX, BX   ; Add the value in register BX to the value in register AX
      JMP LOOP     ; Jump to the label "LOOP"

Line 1: LOOP: MOV AX, 10

  • Components: label LOOP + mnemonic MOV + destination operand AX + source operand 10 (an immediate value — the number itself, not an address).
  • Mnemonic: MOV = "move" (really copy: the source keeps its value).
  • Operands: AX is a 16-bit general-purpose register inside the x86 CPU — think of it as one of the CPU's hands. 10 is the decimal constant ten.
  • Convention (x86): the first operand is the destination, the second is the source: MOV destination, source.
  • Before: AX = unknown (say 0000H).
  • After: AX = 000AH (10 decimal = 0A hex). Nothing else changes.

Line 2: ADD AX, BX

  • Components: mnemonic ADD + destination AX + source BX (a second 16-bit register).
  • Meaning: AX ← AX + BX. The old value of AX is replaced by the sum; BX is unchanged.
  • Before: AX = 000AH, BX = (say) 0005H.
  • After: AX = 000FH (15), BX = 0005H still. The FLAGS register also updates (Section 13).

Line 3: JMP LOOP

  • Components: mnemonic JMP + one operand, the label LOOP.
  • Meaning: unconditional jump — instead of continuing to the next line, the CPU loads the Program Counter with the address that LOOP stands for. Execution resumes at line 1.
  • Effect: this three-line program is an infinite loop: AX is reset to 10, BX is added, jump back, forever. (As a teaching example it shows labels and jumps; a real program would include an exit condition.)

5.5 Why use assembly language? (from the notes)

From Lecture Notes

  • Control over hardware — fine-grained control, letting programmers optimise performance or implement specific hardware features.
  • Debugging — easier to debug because it corresponds directly to machine instructions.
  • Understanding computer architecture — studying assembly teaches how computers work at a low level.

5.6 Advantages and disadvantages (from the notes)

Advantages
  • Precise control over hardware → increased code optimisation.
  • Direct access to hardware components like registers → tailored solutions for hardware issues.
  • Efficient resource utilisation (low-level control, optimised code, resource awareness, customisation).
  • Ideal for microcontrollers, sensors and other hardware components.
  • Used in security research: finding vulnerabilities, reverse engineering.
  • Essential for operating systems, kernels and device controllers that require hardware interaction.
Disadvantages
  • Complex and very hard to learn, especially for beginners.
  • Highly machine-dependent → limits portability.
  • Hard to maintain, especially in large-scale projects.
  • Very time-consuming: hard to understand, very long code.
  • Debugging is challenging.
Key Idea Assembly trades programmer time for machine control. High-level languages trade a little machine efficiency for enormous programmer productivity. Neither is "better" — they serve different jobs.

6 · Machine Language & Machine Instructions

6.1 How a machine executes without understanding

From Lecture Notes The notes make a deep point worth reading slowly: "A computer executes machine language programs mechanically — without understanding them or thinking about them — simply because of the way it is physically put together." A computer is built of millions of tiny switches called transistors, wired so that the output of one switch can turn another on or off. As the computer computes, these switches flip each other in a pattern determined by (a) the wiring and (b) the program being executed. Machine instructions are expressed as binary numbers; each particular sequence of zeros and ones encodes one particular instruction. Data is encoded the same way, because switches readily represent two states: on = 1, off = 0.

Key Idea There is no "reader" inside the CPU that understands your program. Decode-and-execute is a physical cascade: the bits of the instruction energise specific wires, and the wiring makes the right thing happen. This is why the encoding (instruction format) matters so much — the bit positions themselves are the control signals' source.

6.2 What is a machine instruction?

From Lecture Notes

  • Machine instructions are commands written in the machine code of a machine that it can recognise and execute.
  • A machine instruction consists of several bytes in memory that tell the processor to perform one machine operation.
  • The processor looks at machine instructions in main memory one after another, performing one machine operation per instruction.
  • The collection of machine instructions in main memory is called a machine language program.
  • Each instruction performs a very specific task: a load, a jump, or an ALU operation on data in a register or memory. Every program directly executed by a CPU is made of a series of such instructions.

6.3 General format of a machine instruction (assembly view)

From Lecture Notes

[Label:]   Mnemonic [Operand, Operand]   [;comments]
  • Brackets indicate a field is optional.
  • Mnemonic is the symbol for the instruction's operation code.
  • Label is an identifier assigned the address of the first byte of the instruction in which it appears; it must be followed by ":".
  • Spacing is arbitrary, except that at least one space must be inserted — no space would create ambiguity.
  • The comment field begins with a semicolon (;).

7 · How the CPU Executes an Instruction

From Lecture Notes The notes describe program execution like this: the CPU contains a special register — the instruction register (IR) — whose bit pattern determines what the CPU does. Since instructions are simply bit patterns, they can be kept in memory. The instruction pointer (program counter) always holds the memory address of the next instruction to be executed. The notes then give the complete fetch-execute sequence:

The 8-step execution sequence (Lecture 1.3.1)
  1. A sequence of instructions is stored in memory.
  2. The memory address where the first instruction is found is copied to the instruction pointer (PC).
  3. The CPU sends the address in the instruction pointer to memory on the address bus.
  4. The CPU sends a "read" signal on the control bus.
  5. Memory responds by sending a copy of the bits at that location on the data bus, which the CPU copies into its instruction register.
  6. The instruction pointer is automatically incremented to contain the address of the next instruction in memory.
  7. The CPU executes the instruction in the instruction register.
  8. Go to step 3.
Steps 3, 4 and 5 are called an instruction fetch. Steps 3–8 constitute the instruction execution cycle.

7.1 The three buses — what each wire bundle does

Clarification The steps mention three "buses." A bus is a bundle of parallel wires connecting CPU and memory (and I/O). Each bus has one job:

8 · T-States, Bus Cycles, Machine Cycles & Instruction Cycles

From Lecture Notes Clarification The notes introduce three timing terms and four numerical problems. These terms are famously confusing because they are nested — each is built from the previous one. Let us build the hierarchy from the bottom up.

8.1 The clock and the T-state

Every CPU has a clock: an electronic metronome producing a steady square wave — tick, tick, tick — billions of times per second. Nothing inside the CPU happens "whenever"; every action starts on a clock tick.

  • Clock frequency — how many ticks per second, in Hertz (Hz). 1 MHz = 1,000,000 ticks/second; 1 GHz = 109 ticks/second.
  • Clock period — the duration of one tick = 1 / frequency.
  • T-state (From Lecture Notes terminology, standard in 8085 courses) — one clock period. A T-state is the smallest unit of CPU time: the time between two successive clock ticks.
T-state time = 1 ÷ clock frequency
Units: frequency in Hz → time in seconds. Example: 2 MHz → 1 / 2,000,000 s = 0.5 µs (microseconds). Remember: 1 ms = 10⁻³ s, 1 µs = 10⁻⁶ s, 1 ns = 10⁻⁹ s.

8.2 Bus cycle

From Lecture Notes "The bus cycle is the cycle or time required to make a single read or write transaction between the CPU and an external device such as external memory." One bus cycle = one handshake across the buses: address out, control signal out, data across. A bus cycle takes several T-states (on the 8085, typically 3 T-states minimum; extra wait states can be inserted if the memory is slow).

8.3 Machine cycle

From Lecture Notes "The machine cycle is the number of cycles needed to do either a fetch, read or write operation. The read or write may be more than a single bus cycle if the transaction between the CPU and memory is longer than the data width fetched or written."

The notes' example: on an 8085 the data bus is 8 bits wide. If the CPU must fetch or write 16 bits of data, that needs two bus cycles (two 8-bit transfers) but counts as one machine cycle, because it is one logical 16-bit operation using a 16-bit register.

Clarification Named machine cycles you will meet: opcode fetch (reading the instruction's first byte), memory read, memory write, I/O read, I/O write. An instruction like "load accumulator from memory" needs at least two machine cycles: one to fetch the instruction, one to read the data.

8.4 Instruction cycle

The instruction cycle is the total time to fetch and execute one complete instruction — it is made of one or more machine cycles. (Section 11 studies its stages in detail.)

8.6 The lecture's four numerical problems — fully worked

Problem Q1 From Lecture Notes

A microprocessor takes 4 T-states to complete a machine cycle. The clock frequency is 2 MHz. How much time does one machine cycle take?

Given: 1 machine cycle = 4 T-states; clock frequency f = 2 MHz = 2,000,000 Hz.
Required: time of one machine cycle.
Formula: T-state = 1 / f; machine-cycle time = (number of T-states) × (T-state time).
Substitution: T-state = 1 / 2,000,000 s = 0.0000005 s = 0.5 µs.
Calculation: 4 × 0.5 µs = 2 µs.
Final answer: One machine cycle takes 2 µs.
Why this works: The clock is the metronome; every T-state lasts exactly one tick. Four ticks at half a microsecond each give two microseconds. We convert Hz → seconds first because Hz literally means "ticks per second".

Problem Q2 From Lecture Notes

An instruction requires 3 machine cycles: opcode fetch (4 T-states), memory read (3 T-states), and memory write (3 T-states). How many total bus cycles and T-states are needed to execute this instruction?

Given: 3 machine cycles — opcode fetch (4 T), memory read (3 T), memory write (3 T); each machine cycle here is a single bus transaction.
Required: total bus cycles; total T-states.
Formula: totals = sum of the parts.
Calculation: Total bus cycles = 3 (one per machine cycle). Total T-states = 4 + 3 + 3 = 10.
Final answer: 3 bus cycles; 10 T-states.
Why this works: Each of the three machine cycles performs exactly one external transaction (fetch the opcode, read data, write data), so bus cycles = machine cycles = 3 here. The T-states simply add because the operations happen one after another in time. (If one machine cycle had needed two 8-bit transfers, bus cycles would exceed machine cycles — see Section 8.3.)

Problem Q3 From Lecture Notes

A memory read operation takes 3 T-states and there are 2 wait states inserted, and the clock period is 1 µs. What is the total time for this bus cycle?

Given: normal read = 3 T-states; wait states = 2; clock period (1 T-state) = 1 µs.
Required: total bus-cycle time.
Formula: total T-states = normal + wait states; time = total T-states × clock period.
Substitution: total T-states = 3 + 2 = 5.
Calculation: 5 × 1 µs = 5 µs.
Final answer: 5 µs.
Why this works: A wait state is an extra clock tick the CPU inserts to give slow memory time to respond. Each wait state adds exactly one T-state, so 2 wait states stretch a 3-T-state read to 5 T-states.

Problem Q4 From Lecture Notes

A CPU executes an instruction in 16 T-states. If the instruction takes 8 microseconds to complete, what is the clock frequency?

Given: instruction = 16 T-states; total time = 8 µs.
Required: clock frequency f.
Formula: T-state time = total time ÷ T-states; f = 1 / T-state time.
Substitution: T-state = 8 µs / 16 = 0.5 µs = 0.5 × 10⁻⁶ s.
Calculation: f = 1 / (0.5 × 10⁻⁶) = 2 × 10⁶ Hz = 2 MHz.
Final answer: Clock frequency = 2 MHz.
Why this works: Frequency and period are reciprocals. We first find how long one tick lasts (divide total time evenly among 16 ticks), then flip it to get ticks-per-second. Watch the units: 0.5 µs must be written as 0.5 × 10⁻⁶ s before taking the reciprocal, or the answer comes out wrong by a factor of a million.

9 · Why Addressing Modes Exist (Lecture 1.3.2)

From Lecture Notes "The operation field of an instruction specifies the operation to be performed. This operation must be executed on some data stored in computer registers or memory words. The way the operands are chosen during program execution is dependent on the addressing mode of the instruction. The addressing mode specifies a rule for interpreting or modifying the address field of the instruction before the operand is actually referenced."

Computers use addressing modes for two purposes (verbatim from the notes):

  1. To give programming versatility — facilities such as pointers to memory, counters for loop control, indexing of data, and program relocation.
  2. To reduce the number of bits in the address field of the instruction.

9.1 The problem, from first principles

Clarification Recall from Section 0.9 that an instruction contains an opcode plus an operand/address field. Here is the difficulty: the address field is small (say 12 bits, which can name only 212 = 4096 memory cells), but real memory is large, and real programs need flexible ways to reach their data — walking through arrays, following pointers, looping, relocating code. If the address field could only ever mean "the literal memory cell with this number," none of those patterns would be practical.

An addressing mode is therefore an agreement between the programmer and the CPU about how to interpret the address field:

  • "These bits are the data" (immediate),
  • "these bits name a register holding the data" (register),
  • "these bits name a register holding the address of the data" (register indirect),
  • "these bits are the memory address of the data" (direct),
  • "these bits are the address of the address of the data" (indirect),
  • "add these bits to a register to get the address" (indexed / relative)…

Same instruction bits, different interpretation rules, completely different data reached. The mode is signalled either by dedicated mode bits in the instruction or by the opcode itself.

Key Idea An addressing mode answers one question: "Given the bits in the instruction, where is the actual operand?" Every mode is just a different recipe for answering it.

10 · Effective Address (EA)

From Lecture Notes "The effective address refers to the address of the exact memory location in which an operand's value is actually present."

10.1 What "effective" means

Clarification The address field inside the instruction is often not the final address — it may be a displacement, a register number, or a pointer to a pointer. The CPU must compute the real address from those bits. The result of that computation — the address that is effectively used to touch memory — is the effective address. Think of the address field as a clue and the EA as the answer the clue leads to.

10.2 EA vs instruction address

Do not confuse two different addresses living side by side during execution:

  • The instruction address — where the instruction itself sits in memory (tracked by the PC).
  • The effective address — where the instruction's data sits (computed per the addressing mode).

10.1 · Implied Mode

From Lecture Notes "In this mode the operands are specified implicitly in the definition of the instruction. For example, the instruction 'complement accumulator' is an implied-mode instruction because the operand in the accumulator register is implied in the definition of the instruction. In fact, all register-reference instructions that use an accumulator are implied-mode instructions."

What problem does it solve?

Some operations always act on the same register. Why waste bits naming it? Implied mode makes instructions short and fast by hard-wiring the operand into the opcode.

How it works & example

CMA   ; Complement Accumulator — flip every bit of AC
  • Effective address: none — the operand is the accumulator, named by the opcode itself.
  • Before: AC = 0F0FH (0000 1111 0000 1111).
  • After: AC = F0F0H (1111 0000 1111 0000). No memory touched, no operand field needed.

Advantages / disadvantages / when useful

  • + Shortest possible encoding (opcode only); no operand fetch; very fast.
  • − Completely inflexible — works only on the one implied register.
  • Useful for: frequent single-register housekeeping: complement, clear, increment accumulator, halt, no-operation.
Common Confusion Implied ≠ immediate. Implied: the operand is a fixed register hidden in the opcode. Immediate: the operand is a constant written inside the instruction. Both need no memory access, but for opposite reasons.

10.2 · Immediate Mode

From Lecture Notes "In the immediate mode, we specify the operand in the instruction itself. Instead of an address field, the immediate-mode instruction consists of an operand field containing the actual operand. Immediate-mode instructions help initialise registers to a constant value."

What problem does it solve?

Programs constantly need constants: loop limits, initial values, masks. Fetching a constant from memory would waste a memory cell and a bus cycle. Immediate mode embeds the constant in the instruction stream.

How it works & examples (from the notes)

MOV A, #55H   ; 8051: the '#' marks immediate data — move the value 55H into A
MVI A, 55H    ; 8085: Move Immediate (no '#' needed; the opcode implies it)
  • Effective address: none — the operand rides inside the instruction. (Formally, the operand's "address" is the location right after the opcode, which is why the PC slides past it.)
  • Before: A = anything. After: A = 55H. Memory data cells: untouched.

Advantages / disadvantages / when useful

  • + No extra memory access → fast; perfect for constants.
  • − The value is frozen at assembly time — you cannot change it at run time; constant size limited by field width.
  • Useful for: initialising registers/counters, comparing against fixed limits.
Common Confusion MOV A, #55H (immediate) puts the number 55H into A. MOV A, 55H (direct, next-but-one mode) puts the contents of memory cell 55H into A. One # changes everything.

10.3 · Register Mode (Register Direct)

From Lecture Notes "In the register mode, the operands exist in registers that reside within the CPU. We select a specific register from a register field in the instruction. A k-bit field can determine one of 2k registers."

What problem does it solve?

Memory is far away; registers are inside the CPU. If the data is already in a register, the instruction should be able to say "use register 3" in 3–4 bits instead of spending 12–32 bits on a memory address — this is the notes' second purpose of addressing modes (fewer bits) in its purest form.

How it works & example

MOV A, B   ; copy the contents of register B into register A
  • Effective address: none — no memory access at all. The "address" is a register number inside the CPU.
  • Before: A = 11H, B = 7CH. After: A = 7CH, B = 7CH (copy, not move-and-erase).

Advantages / disadvantages / when useful

  • + Fastest data access in the machine; tiny address field (k bits select 2k registers).
  • − Only works for data already in registers; registers are scarce.
  • Useful for: arithmetic on active variables, shuffling values between working registers.

10.4 · Register Indirect Mode

From Lecture Notes "The instruction defines the particular register in the CPU whose contents provide the operand's address in memory. The selected register includes the address of an operand instead of the operand itself. The advantage: the instruction's address field uses fewer bits to select a register than would be required to directly specify a memory address."

What problem does it solve?

A 3-bit register field can only name 8 registers — but each register can hold a full-width address (16, 32, 64 bits). So a tiny instruction field can reach anywhere in memory, and the pointer can be changed at run time. This is how pointers in C actually work underneath.

Step-by-step example (from the notes)

; 8051: suppose R0 = 40H and M[40H] = 25H
MOV A, @R0   ; A ← M[R0] → A = 25H   ('@' means "indirect through")
; 8086:

  • State trace: R0 = 40H (unchanged), M[40H] = 25H (unchanged), A: ? → 25H.

Advantages / disadvantages / when useful

  • + Full memory reach with a tiny field; pointer can be computed/changed at run time; only one memory access.
  • − One memory access still required (slower than register mode); needs a register reserved as pointer.
  • Useful for: pointers, walking data structures, passing large objects by reference.

10.5 · Auto-increment / Auto-decrement Mode

From Lecture Notes "Very similar to register indirect mode. Available in 8051, PDP-11 or ARM. The only difference: the register is decremented or incremented before or after its value is used to access memory. When the address stored in the register defines a data table in memory, it is crucial to increment or decrement the register after each access."

What problem does it solve?

Processing arrays element-by-element needs two actions per element: access M[pointer], then move the pointer. This mode fuses them into one instruction — the pointer updates itself automatically. It is also exactly how hardware stacks implement PUSH (auto-decrement) and POP (auto-increment).

How it works & examples (from the notes)

; Auto-increment (conceptual notation):
MOV A, @R0+   ; A ← M[R0], then R0 ← R0 + 1
; (the notes clarify: on a real 8051 you write INC R0 after the indirect access)

; Auto-decrement on 8051 (from the notes):
MOV R0, #35H  ; initialise pointer at 0x35
DEC R0        ; R0 → 0x34 (point to previous address)
MOV A, @R0    ; A ← M[34H]
  • Effective address: EA = contents of the register (the update happens before or after the access, depending on convention).
  • State trace (auto-increment): suppose R0 = 40H, M[40H] = 25H. After MOV A, @R0+: A = 25H and R0 = 41H — the register changed, unlike plain register indirect.

Advantages / disadvantages / when useful

  • + One instruction does access + pointer update → shorter, faster loops; natural stack operations.
  • − The register is modified as a side effect — a common source of bugs if forgotten.
  • Useful for: array/table traversal, stack PUSH/POP, sequential I/O buffers.
Common Confusion Register indirect leaves the pointer register unchanged; auto-increment/decrement changes it. When tracing code, always check whether the mode updates the register.

10.6–10.9 · The Memory-Based Modes

10.6 · Direct Address Mode

From Lecture Notes "In the direct address mode, the address part of the instruction is equal to the effective address. The operand resides in memory, and the address is given directly by the instruction's address field. In a branch-type instruction, the address field specifies the actual branch address."

What problem does it solve?

The simplest way to reach memory: just say the address. No registers, no arithmetic. Ideal for named variables at fixed locations.

How it works & example

MOV A, 30H   ; move the CONTENT of memory cell 30H into accumulator A
Instruction address field = 30H
↓ EA = 30H (the field is the address)
Memory cell 30H → contains the DATA → loaded into A
  • Effective address: EA = address field = 30H.
  • State: if M[30H] = 99H, then after execution A = 99H; memory unchanged.

Advantages / disadvantages / when useful

  • + Simple to understand and decode; only one memory access.
  • − Address is fixed at assembly time; field width limits reachable memory (12 bits → only 4K cells).
  • Useful for: accessing global/static variables, branch targets.

10.7 · Indirect Address Mode

From Lecture Notes "In indirect address mode, the address field of the instruction gives the address in which the effective address is stored in memory. The control fetches the instruction and then uses its address part to (again) access memory to read the effective address."

What problem does it solve?

The pointer lives in memory, not in a register. This lets a small address field reach full-width addresses (the cell it points to holds a complete address), and the pointer can be updated by the program without changing the instruction — the classic way to implement pointers and dynamic data structures on simple machines.

How it works & example (from the notes)

MOV A, 31H  ; INDIRECT: if M[31H] = 55H and M[55H] = 35H, then A = 35H
Instruction address field = 31H
↓ first memory read
M[31H] = 55H ← this is the effective address
↓ second memory read
M[55H] = 35H ← this is the data, loaded into A
  • Effective address: EA = M[address field] = M[31H] = 55H; operand = M[55H] = 35H.
  • Memory accesses: two — one to fetch the pointer, one to fetch the data.
Note on the notes The lecture writes this example with the same syntax as its direct-mode example (MOV A, 31H) and relies on the comment to signal indirection. Real assemblers distinguish the modes explicitly — e.g. MOV A, @31H or LDA (31H). Treat the notes' notation as conceptual; the concept (address → address → data) is what matters.

Advantages / disadvantages / when useful

  • + Full-width addresses through a small field; pointer can change at run time.
  • − Two memory accesses → slower; harder to follow when reading code.
  • Useful for: pointers stored in memory, jump tables, dynamically located data.

10.8 · Indexed Address Mode

From Lecture Notes "The content of an index register is added to the instruction's address part to obtain the effective address. The index register is a special CPU register holding an index value; the instruction's address field defines the beginning address of a data array in memory." And the general formula from the notes:

EA = address part of instruction + content of CPU register
The notes generalise: the register may be an index register, a base register, or the program counter — each choice gives a different named mode (indexed / based / relative).

What problem does it solve?

Arrays. If table starts at address 200H and you want element i, the address is 200H + i. Put 200H in the instruction (fixed) and i in the index register (variable, changed by the loop) — one instruction form serves every element.

How it works & example

; conceptual: load A with table[i]
; address field = 200H (start of table), index register X = 05H
MOV A, 200H(X)  ; EA = 200H + 05H = 205H → A ← M[205H]
  • Effective address: EA = 200H + (X) = 205H.
  • State: X = 05H (unchanged), M[205H] copied into A. Next loop iteration: increment X to 06H → the same instruction now reads M[206H].

Advantages / disadvantages / when useful

  • + Perfect for arrays and records; one instruction walks the whole table as the index changes.
  • − Needs an adder step in the CPU (EA computation takes time); uses up a register as the index.
  • Useful for: array indexing, struct field access, loop-controlled data processing.

10.9 · Relative Address Mode

From Lecture Notes "The effective address is calculated by adding the content of the CPU register [the program counter] to the address part of the instruction word. The effective address is the sum of the displacement and the value of the register. The address part is typically a signed number, which can be negative or positive. The resultant effective address is relative to the address of the next instruction." The notes give the symbolic form and formula:

X(PC)  →  EA = X + (PC)
X = signed displacement stored in the instruction; (PC) = current content of the program counter. Because the operand is found relative to the PC, this is the relative address mode.

What problem does it solve?

Position-independent code. If a program is loaded at a different memory address, absolute branch targets break — but a target expressed as "40 bytes ahead of where we are now" works anywhere. This is how real branch instructions on most CPUs (x86, ARM, MIPS) are encoded.

How it works & example

; suppose PC = 100H (pointing at next instruction) and displacement X = +25H
JMP +25H  ; EA = 25H + 100H = 125H → execution continues at 125H
  • Effective address: EA = 25H + 100H = 125H.
  • Signed displacement: X = −10H would give EA = 100H − 10H = F0H — a backward jump (loops!).

Advantages / disadvantages / when useful

  • + Code can be relocated anywhere in memory; displacements are small (few bits) since targets are usually nearby.
  • − Range is limited by the displacement field's width.
  • Useful for: branch/jump instructions, loops, relocatable programs.

11 · The Instruction Cycle

From Lecture Notes "The time a microprocessor needs to fetch and execute one entire instruction is known as an instruction cycle." The notes describe four typical stages:

The four stages (Lecture 1.3.2)
  1. Fetch the instruction — the next instruction is fetched from the memory address stored in the PC and placed in the IR. At the end of the fetch, the PC points to the next instruction.
  2. Decode the instruction — the encoded instruction in the IR is interpreted by the decoder.
  3. Read the effective address — for a memory instruction with indirect addressing, the effective address is read from memory and the data fetched into data registers (clock pulse T3). If the instruction is direct, nothing is done at this pulse. If it is an I/O or register instruction, execution happens here.
  4. Execute the instruction — the control unit passes decoded information as control signals to the functional units: values read from registers, passed to the ALU, results written back. If the ALU is involved it sends a condition signal back to the control unit. The result is stored in memory or sent to an output device. Based on ALU feedback, the PC may be updated to a different address (a branch).

ADD / SUB — the workhorses

ADD AX, BX → AX ← AX + BX. Before: AX=0010H, BX=0005H. After: AX=0015H, BX unchanged; flags record properties of the sum. SUB AX, BX → AX ← AX − BX, same pattern.

MUL / DIV — note the asymmetry on x86

Clarification On x86, MUL BX multiplies the implicit AX by BX, storing the full 32-bit product in DX:AX (two registers) — because a 16×16-bit product can need 32 bits. DIV BX likewise divides the 32-bit DX:AX pair by BX, leaving the quotient in AX and the remainder in DX. The notes' generic MUL R1, R2 form simplifies this; on many RISC machines (e.g., MIPS) you do get a clean three-operand form.

INC / DEC — +1 and −1

INC AX → AX ← AX + 1. Before AX=00FFH → after AX=0100H. Used constantly for loop counters and pointer updates (the DEC R0 from Section 10.5 is the same idea). They exist as separate instructions because they encode shorter than ADD AX, 1.

NEG — flip the sign

NEG AX computes the two's-complement negation: AX ← 0 − AX. Before AX=0005H → after AX=FFFBH (−5 in two's complement).

ADC / SBB — arithmetic with carry/borrow

Clarification ADC AX, BX → AX ← AX + BX + Carry flag. SBB AX, BX → AX ← AX − BX − Carry flag (borrow). Why include the carry? To chain multi-word arithmetic: when adding 32-bit numbers as two 16-bit halves, the carry out of the low half must flow into the high half. First ADD the low halves, then ADC the high halves.

Clarification Classic uses: AND masks bits off (clear unwanted bits), OR sets bits, XOR toggles bits — and XOR AX, AX is the standard trick to zero a register.

TEST — AND without the result

TEST AX, BX computes AX AND BX temporarily and only updates the flags — most importantly the Zero flag. The classic idiom TEST AX, AX answers "is AX zero?" without destroying AX (ZF=1 if AX was 0).

SHL / SHR — shifts (moving bits off the edge)

ROL / ROR — rotates (bits that fall off come back on the other side)

Clarification The stack is a last-in-first-out (LIFO) area of memory managed by a register called the Stack Pointer (SP). PUSH: SP moves (downward on x86/8085), value written to the new top. POP: top value copied out, SP moves back.

IN / OUT — talking to devices

IN AX, 60H reads a 16-bit word from I/O port 60H (e.g., a keyboard controller) into AX; OUT 60H, AX writes AX to port 60H. Ports are addressed separately from memory on x86 (see Section 14.3).

LEA — address, not contents

Clarification LEA AX, [BX+SI] computes the effective address (BX+SI) and puts the address itself into AX — no memory read. Contrast: MOV AX, [BX+SI] would load the contents of that address. LEA exists so pointer arithmetic can be done explicitly.

XCHG — swap in one step

XCHG AX, BX: before AX=0007H, BX=00F0H → after AX=00F0H, BX=0007H. One instruction, no temporary register needed.

NOP — deliberately doing nothing

Clarification NOP consumes an instruction cycle but changes nothing. Uses: padding for timing alignment, placeholders for patching code, and crude delay loops. On x86 it is the single byte 0x90.

HLT / WAIT — stopping and pausing

HLT freezes the CPU (until a hardware reset or, on x86, an enabled interrupt) — used by OS shutdown paths and idle loops. WAIT pauses until an external pin/signal says "ready" — historically used to synchronise with a floating-point coprocessor.

CLC / STC / CLI / STI — hand-editing the flags

These four are implied-mode instructions that directly set or clear one flag bit. CLC before ADC-chains guarantees a clean starting carry. CLI/STI disable/enable hardware interrupts — critical when an OS must guarantee an uninterruptible sequence (Section 14.3 explains interrupts).

JMP / CALL / RET — redirecting the PC

  • JMP 2000H: PC ← 2000H. Execution simply continues elsewhere. The one-way door.
  • CALL 3000H: PUSH the address of the next instruction onto the stack, then PC ← 3000H. A two-way door — it remembers where home is.
  • RET: POP the stacked address back into the PC. Returns to the instruction right after the CALL. This CALL/RET pair is the machine-level basis of functions/methods in every language.

INT n / RST n — software interrupts and restart vectors

Clarification INT 21H on x86 triggers a software interrupt: the CPU saves its state and jumps to a pre-registered handler — the classic DOS system-call mechanism (INT 21H was the DOS API). The 8085's RST n is a compact one-byte call to one of eight fixed addresses (n×8) in low memory — used for hardware interrupts and breakpoints.

13 · Flags / Condition Codes (Z, S, O, C)

From Lecture Notes "At the end of execution of arithmetic and logical instructions, depending on the result in the Accumulator, Condition Codes (Zero, Sign, Overflow, Carry — ZSOC) are set, implying the outcome of the instruction execution. Generally, these flags are useful in controlling the flow of the program."

13.1 What a flag is

Clarification A flag is a single-bit register in the CPU's status/flags register. After every arithmetic/logical operation, the ALU doesn't just produce a result — it also produces yes/no facts about that result:

FlagNameSet (=1) when…Typical question it answers
ZZerothe result is exactly 0"Were the two values equal?" (SUB sets Z if equal)
SSignthe result's most-significant bit is 1 (negative in two's complement)"Is the result negative?"
OOverflowa signed operation produced a result outside the representable range"Did signed arithmetic break?"
CCarryan unsigned addition carried out of the top bit, or a subtraction borrowed"Did unsigned arithmetic wrap around?"

13.2 Result vs flags — the crucial distinction

The result (e.g., the sum in AX) and the flags (Z/S/O/C) are separate outputs of the ALU. The result says what you got; the flags say what kind of thing happened while getting it. Conditional branches (JZ jump-if-zero, JNZ jump-if-not-zero, JC jump-if-carry…) read only the flags — that is how arithmetic controls program flow, as the notes say.

14 · Types of Instructions — the 16-bit Format

From Lecture Notes "Instructions are a set of machine language instructions that a particular processor understands and executes." The notes present a 16-bit instruction divided into fields (this is the classic teaching model from M. Morris Mano's Computer System Architecture):

  • Mode field (I) — 1 bit, bit 15 — specifies how the operand will be located (direct vs indirect).
  • Opcode field — 3 bits, bits 14–12 — specifies what operation to perform.
  • Address field — 12 bits, bits 11–0 — specifies where the operand is (register or memory location).
I / Modebit 15
Opcodebits 14–12

Clarification Why split into fields at all? Because the control unit's decoder is hardware: wires 15, 14–12, and 11–0 route to different circuits. Bit 15 steers the addressing-mode logic; bits 14–12 steer the operation selector; bits 11–0 feed the address path. The field boundaries are literally where the wires go.

14.0 The three instruction types, decided by two levels of inspection

From Lecture Notes The rule from the document's closing note:

How the control unit classifies a 16-bit instruction
  1. Look at bits 14–12 (opcode): if they are not 111, the instruction is a memory-reference instruction; bit 15 then selects direct (I=0) or indirect (I=1) addressing.
  2. If bits 14–12 are 111, look at bit 15:
    • I = 0 → register-reference instruction.
    • I = 1 → input/output instruction.
In both non-memory cases, the 12 address bits specify a register operation or an I/O operation instead of a memory address.

  2. Register-reference; e.g., CMA / CLA / INC / HLT (or x86 MOV AX, BX, INC AX).
  3. No memory-access cycle is needed — registers are inside the CPU.
  4. Port-based: devices live in a separate port address space, reached with IN/OUT. Memory-mapped: device registers occupy normal memory addresses, reached with ordinary load/store.
  5. DMA — a controller transfers whole blocks directly between device and memory.

15 · Instruction Set Classification (Lecture 1.3.4)

From Lecture Notes "The instruction set of any processor broadly fits into categories. The first five are mandatory; the next four are generally available in advanced/new-generation processors. The number of instructions in a processor may range from under 100 to a few hundred; a large instruction set does not imply a powerful processor — often, variants of each instruction are added for downward compatibility within a processor family. Examples below are mnemonic code; R means a CPU register; named words (e.g., Total) are variables; they pertain to no particular CPU."

The nine categories

1 · Data Movement (mandatory)

Move data register↔register, register↔memory (some CPUs even memory↔memory). Named "Move" or "Load/Store". Most frequently used by the CPU while executing program code.

Move  R1, Total    ; R1 ← Total (memory → register)
Move  Total, R1    ; Total ← R1 (register → memory)
Load  R1, Total    ; load form of the same idea
Store R1, Total    ; store form

2 · Arithmetic and Logical (mandatory)

Minimum set: ADD, SUB, AND, OR, XOR, SHIFT. Multiply/divide can be emulated by repeated addition/subtraction (and were, in early systems), but hardware MULTIPLY/DIV is more efficient and is standard now. Logical instructions implement condition checking for for/while loops and if. Condition codes (ZSOC) set after each — same as Section 13.

ADD  R1, Total        ; R1 ← R1 + Total (two-address)
ADD  R1, R2, R3       ; R1 ← R2 + R3 (three-address)
XOR  R4, Total        ; R4 ← R4 XOR Total
MUL  R4, MARKS        ; R4 ← R4 × MARKS

3 · Transfer / Control (mandatory)

Change program flow: BRANCH/JMP plus condition-code flags; subroutine CALLs and RETURNS.

JMP  LABLE1   ; jump
JNZ  LABLE1   ; jump if not zero
BZ   LABLE2   ; branch if zero
BNE  LABLE3   ; branch if not equal

4 · Input/Output (mandatory)

Two ways to do I/O: the Intel family uses IN and OUT instructions on numbered ports ("I/O-mapped I/O"); the Motorola family assigns memory addresses to I/O registers and uses ordinary data-movement instructions ("memory-mapped I/O").

IN   Port#232      ; read port 232
OUT  Port#234      ; write port 234
Move R1, #FFEEEE   ; memory-mapped: write to the register at address FFEEEE

5 · Miscellaneous (mandatory)

NOP (dummy but useful), HALT (stops the system, e.g. on "shutdown"), INT (user-defined interrupts activated by instruction). System control is grouped here or with control instructions.

HALT
NOP
INT

6 · Floating-Point (advanced)

Specialised hardware, working independently of the CPU core, performs floating-point arithmetic efficiently; unique opcodes drive it.

FLD    ; floating-point load
FST    ; floating-point store
FADD   ; floating-point add
FSUB   ; floating-point subtract
FMUL   ; floating-point multiply

7 · Binary-Coded-Decimal (advanced)

Dedicated decimal hardware speeds up decimal calculations; without it, every operation would require binary↔decimal conversion. Like floating point, special decimal hardware and opcodes exist.

8 · Vector (advanced)

Specific to display/graphics: zoom, resize, flip and matrix operations need heavy vector calculations, so vector instructions operate on whole arrays at once.

9 · Emulated (rare)

User-defined opcode and operation; very few CPUs support this.

Purpose ≠ Format Categories 1–9 classify instructions by what they do (purpose). Sections 17–19 classify instructions by how they are encoded in bits (format). An ADD is "arithmetic" by purpose and maybe "two-address" by format. Mixing these two axes is a classic exam trap.

16 · RISC vs CISC

From Lecture Notes "CPU architecture design differs radically based on the size of the instruction set, giving two categories: Reduced Instruction Set Computer (RISC) and Complex Instruction Set Computer (CISC). RISC has fewer instructions; CISC has a large number. Both are equally functionally complete. MIPS, ALPHA, PA-RISC, Intel i860, Motorola 88000, ARM are RISC CPUs. Intel x86, Motorola 68K, VAX are CISC CPUs. The trade-off is between size of program code and simplicity of decoding by hardware."

17.2 Source vs destination operand

Clarification In multi-operand instructions, operands have roles: the source supplies data, the destination receives the result. In ADD R1, R2, R3 (three-address), R2 and R3 are sources, R1 is destination. In ADD R1, R2 (two-address), R1 is both source and destination — an economy that matters below.

17.3 Key design considerations (from the notes)

  1. Length — shorter instructions save memory but limit functionality; longer ones encode more.
  2. Number of operands — affects instruction size and flexibility; zero to three operands are common.
  3. Addressing modes — determine how operands are accessed, influencing complexity.
  4. Ease of decoding — fixed-length formats simplify decoding but may waste memory; variable-length formats save memory but complicate decoding.

18 · Fixed-Length vs Variable-Length Formats

18.1 Fixed-length (from the notes)

From Lecture Notes "RISC uses fixed-length encoding in which each instruction occupies the same amount of space, irrespective of the opcode. It simplifies instruction decoding. Example: the MIPS series — a RISC processor with only 3 format variants, all the same word length; also, registers (not memory) are used for referencing operands."

External Research The MIPS formats are the textbook example (MIPS documentation):

opcode6 bits
rs5 bits
rt5 bits
rd5 bits
shamt5 bits
funct6 bits

MIPS R-type (register) format — always exactly 32 bits. The I-type replaces rd/shamt/funct with a 16-bit immediate; J-type with a 26-bit jump address. Same length, three layouts.

Advantages
  • Decoder always knows where fields sit → simple, fast, pipeline-friendly.
  • PC advances by a constant → trivial next-address computation.
Disadvantages
  • Wastes space on simple instructions (padding bits).
  • Limited flexibility in what one instruction can express.

18.2 Variable-length (from the notes)

From Lecture Notes "CISC uses variable-length encoding in which each instruction occupies only the space required to convey its operands — no redundant memory use. It allows compact representation but complicates decoding. Example: the Motorola M6800 CISC CPU." The notes describe a supporting figure: "there are 8 ways in which the instruction is encoded, varying from 2 bytes to 8 bytes; the length differs depending on how the operand address is conveyed."

LengthReason
2 bytesshort opcode + small operand/offset (e.g. branch offset)
3–4 bytesopcode + medium address/displacement
…more complex addressing → more operand bytes
up to 8 bytesopcode + full-width immediate/address fields

Clarification x86 is the extreme case: instructions range from 1 byte (NOP = 0x90) to 15 bytes. The decoder must read the first byte, work out how long the instruction is, and only then can it find where the next instruction begins — the price of compact code.

Advantages
  • Compact code — no padding bits wasted.
  • Can express complex operations in one instruction.
Disadvantages
  • Decoding is hard: length must be discovered per instruction.
  • PC advance varies → complicates pipelining and branch prediction.
Not absolute laws (repeat of Section 16) Associate fixed-length with RISC-style simplicity and variable-length with CISC-style compactness as typical relationships. Real architectures mix approaches; treat the mapping as a strong tendency, not a definition.

19 · Zero-, One-, Two-, Three-Address Instructions

From Lecture Notes The document classifies instruction formats by how many address fields they contain and evaluates the same arithmetic expression in all four styles. Zero-address — stack based

Clarification A stack machine keeps operands on the hardware/OS stack (LIFO). PUSH X puts a value on top; an operation like ADD pops the top two values, adds them, and pushes the result. Since the operands live on the stack top, no address field is needed — instructions shrink to just the opcode. The price: extra PUSH/POP traffic and the need to track stack order carefully.

One-address — accumulator based

One implied accumulator supplies one operand and receives the result; the explicit field names the other operand. The price: constant LOAD/STORE traffic between memory and AC (accumulator organisations are covered in Lecture 2.1.1 of the same course).

Two-address — one operand doubles as destination

One field doubles as source and destination, so ADD R1, R2 destroys R1's old value. Fewer bits than three-address, but the overwrite must be planned for (often needing a preliminary MOV).

Three-address — cleanest, costliest

Both sources and a separate destination are named: no operand is destroyed, and expressions compile to few, readable instructions. The price: wide instructions (three fields) and a bigger register file to decode.

20 · Problem Solving

This section collects every numerical problem from the lecture document (Q1–Q4, fully worked in Section 8.6) and adds graded practice covering clock period/frequency, T-states, machine cycles, bus cycles, wait states, instruction execution time, effective-address calculations, and instruction-format bit allocation.

Part A — Timing problems (P1–P5, increasing difficulty)

Practice P1

A CPU runs at 4 MHz. What is the duration of one T-state?

Given: f = 4 MHz. Required: T-state time.
Formula: T = 1/f. Substitution: 1 / 4,000,000 = 0.25 × 10⁻⁶ s. Answer: 0.25 µs (250 ns)
Practice twin (try yourself): at 6 MHz → 1/6,000,000 ≈ 0.167 µs = 167 ns.

Practice P2

An opcode-fetch machine cycle contains 6 T-states at 2.5 MHz. How long does it take?

Given: 6 T-states; f = 2.5 MHz. Required: time.
Formula: time = n × (1/f). Calculation: T-state = 1/2.5 MHz = 0.4 µs; 6 × 0.4 = 2.4 µs. Answer: 2.4 µs
Practice twin: 5 T-states at 1 MHz → 5 × 1 µs = 5 µs.

Practice P3

A memory-write bus cycle normally takes 4 T-states, but a slow peripheral inserts 3 wait states. Clock period = 0.5 µs. Find the total time.

Given: 4 + 3 = 7 T-states; 0.5 µs each. Calculation: 7 × 0.5 = 3.5 µs. Answer: 3.5 µs
Why: each wait state adds exactly one T-state (see Q3, Section 8.6).

Practice P4

An instruction uses 4 machine cycles: opcode fetch (6 T), memory read (4 T), memory read (4 T), memory write (3 T). Clock = 2 MHz. Find total T-states, bus cycles, and execution time.

T-states: 6+4+4+3 = 17. Bus cycles: 4 (one per machine cycle). Time: 17 × 0.5 µs = 8.5 µs
Why: this mirrors Q2 of the notes — machine cycles and bus cycles coincide when each operation is a single transaction.

Practice P5 (hardest)

An instruction takes 21 T-states and executes in 4.2 µs. (a) Find the clock frequency. (b) How many wait states are in this instruction if its minimum is 18 T-states?

(a) T-state = 4.2 µs / 21 = 0.2 µs → f = 1/(0.2 × 10⁻⁶) = 5 MHz.
(b) 21 − 18 = 3 wait states.
Why: same reciprocal trick as Q4 of the notes; wait states inflate the minimum T-state count.

Part B — Effective-address calculations (P6–P8)

Practice P6

Index register X = 07H; instruction address field = 3A0H; M[3A7H] = 66H. (a) EA = ? (b) What value is loaded by an indexed LOAD?

(a) EA = 3A0H + 07H = 3A7H. (b) operand = M[3A7H] = 66H. Classic indexed mode (Section 10.8).

Practice P7

Given M[40H] = 99H and M[99H] = 21H. An instruction's address field is 40H. Find the EA and the loaded value under (a) direct mode, (b) indirect mode.

(a) Direct: EA = 40H → value = M[40H] = 99H. (b) Indirect: EA = M[40H] = 99H → value = M[99H] = 21H. Same bits, different rule — exactly why the mode bit exists.

Practice P8

A branch instruction uses relative mode. At execution, PC (next instruction) = 150H; signed displacement = −30H. Where does control go?

EA = 150H + (−30H) = 120H — a backward branch, e.g. a loop (Section 10.9).

Part C — Instruction-format bit allocation (P9–P10)

Practice P9

An instruction is 16 bits: 1 mode bit, 3-bit opcode, 12-bit address. (a) How many distinct memory cells can be directly addressed? (b) How many memory-reference opcodes are available?

(a) 2¹² = 4096 cells (4K words). (b) opcode values 000–110 → 7 opcodes (111 is reserved for register/I-O types — Section 14).

Practice P10

A format has a 4-bit register field. (a) How many registers can it name? (b) If the same 16-bit instruction must fit a 4-bit opcode and two register fields, how many bits remain for addressing modes/immediate data?

(a) 2⁴ = 16 registers. (b) 16 − 4 − 4 − 4 = 4 bits remain. Register fields are cheap — this is the notes' purpose #2 (fewer bits) in action.
